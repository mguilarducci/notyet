# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

A `Makefile` wraps the common flows (it loads `.env` and exports it, so DB-backed targets get `DATABASE_URL`). One command per line — no compound shell anywhere in this repo (Makefile, scripts, Dockerfile, compose).

- `make db-up` — start the dev Postgres container (`docker compose up -d postgres`)
- `make migrate` — apply pending migrations (`gleam run -m cigogne all`)
- `make migrate-new NAME=foo` — scaffold a new migration in `priv/migrations`
- `make sqlgen` — regenerate typed query modules from `*.sql` (`gleam run -m squirrel`); needs a **live, migrated** DB (squirrel introspects it)
- `make test` — run the full gleeunit suite. **Requires Postgres up + migrated** (`make db-up && make migrate` first) — many tests hit a live DB
- `make run` — start the HTTP server locally
- `make build` / `make deps` — compile / fetch deps
- `docker compose up --build` — full containerized stack: postgres → migrate (one-shot) → app (production Erlang shipment)

gleeunit has no built-in single-test filter; the runner executes all `*_test` functions it discovers. To narrow scope while iterating, temporarily reduce the test module under edit.

## Environment

All variables are **mandatory** — `main()` reads each with `let assert` and panics at boot if any is missing or unparseable. No dev fallbacks. See `.env.example`.

- `DATABASE_URL` — pog Postgres connection URL (`postgres://…`).
- `SECRET_KEY_BASE` — wisp signing key.
- `PORT` — server port.
- `WAIT_BATCH_MAX_SIZE` — flush the write buffer when it reaches this many rows.
- `WAIT_BATCH_INTERVAL_MS` — flush this long after the first pending row.
- `WAIT_BATCH_ACK_TIMEOUT_MS` — how long a request waits for its batch to commit. **Must exceed `WAIT_BATCH_INTERVAL_MS`** (plus insert time), or requests time out before their batch flushes. Keep `INTERVAL_MS` + insert time under pog's 5s per-query timeout.

## Architecture

Gleam web service built on **wisp** (web framework: routing, middleware, request/response) served by **mist** (HTTP server), bridged by `wisp_mist.handler`. Persistence is **Postgres via `pog`**, with typed queries generated by **`squirrel`** and migrations managed by **`cigogne`**. Accepted waits are written through an in-memory **write-behind batching actor** (`gleam_otp`).

Request flow:

```
mist (HTTP) → wisp_mist adapter → router.handle_request(req, ctx)
            → web.middleware → wait.create → batch writer actor → Postgres (batch insert)
```

- **`src/notyet.gleam`** — entrypoint. Reads all env (mandatory) via `envoy`; starts a `static_supervisor` (OneForOne) supervising the `pog` connection pool **and** the batch writer; recovers the writer's `Subject` via a named process; builds the `Context`; wires `router.handle_request` through `wisp_mist` + `mist` (bound to `0.0.0.0` so it is reachable in a container). No business logic.
- **`src/notyet/router.gleam`** — single dispatch point. Applies `web.middleware`, then matches `wisp.path_segments(req)` + `req.method`. Pattern: `["wait"], Post -> handler`, `["wait"], _ -> 405`, `_ -> 404`.
- **`src/notyet/web.gleam`** — shared web concerns: the `Context` type (`batch: Subject(batch.Message)` + `ack_timeout_ms: Int`, threaded to every handler) and `middleware` (method override, request logging, crash rescue, HEAD handling).
- **`src/notyet/wait.gleam`** — the feature module: request type (`WaitRequest`), decoders (`wait_decoder` + private `for_decoder`/`activity_decoder`), response encoder (`encode_response`), and the `create` handler.
- **`src/notyet/wait/duration.gleam`** — pure strict duration-string parser → `gleam_time` `Duration`. No wisp/json deps.
- **`src/notyet/wait/json_value.gleam`** — recursive `JsonValue` ADT with `decoder`/`object_decoder`/`encode` (lossless round-trip). Used for the `data` field.
- **`src/notyet/wait/status.gleam`** — `Status` state machine (`Received`/`Waiting`) with `to_string`/`from_string`. `Received` is the initial state; `Waiting` is reserved (no transitions yet).
- **`src/notyet/wait/record.gleam`** — `WaitRecord`, the dependency-free row type built by the handler and consumed by the batch writer + encoder. Lives alone to break a `wait`↔`batch` import cycle.
- **`src/notyet/wait/batch.gleam`** — write-behind batching actor. `enqueue(subject, record, timeout)` blocks the caller until the record's batch is flushed (ack-on-flush). Flushes on `WAIT_BATCH_MAX_SIZE` rows **or** `WAIT_BATCH_INTERVAL_MS` (whichever first), as one `INSERT … SELECT unnest(...)` query. On commit every waiter in the batch gets `Ok`; on failure every waiter gets `Error` → `500`. `id` + timestamps are minted app-side (not by the DB) because `RETURNING` order from an `unnest` insert is not guaranteed.
- **`src/notyet/wait/sql.gleam`** — squirrel-generated typed query module (from `src/notyet/wait/sql/*.sql`). Regenerate with `make sqlgen`. Do not hand-edit.
- **`priv/migrations/`** — cigogne migrations; **`priv/cigogne.toml`** — cigogne config (falls back to `DATABASE_URL`).

`POST /wait` contract: requires JSON body `{"for": <duration string>, "activity": <uuid v4>, "data"?: <json object>}` → `201 {"id": <uuid v4>, "activity": <uuid v4>, "status": "received", "created_at": <rfc3339 UTC>, "for": <rfc3339 UTC>}` where `created_at` is the moment handled (`now`) and `for` is `now + duration`, both from a single `now` capture. Timestamps end in `Z` (UTC). The wait is **persisted** to the `waits` table via the batched write-behind path; a failed flush or ack timeout → `500`. `activity` is **required** and validated as a strict **UUID v4** (`uuid.from_string` + `version == V4`); missing/non-string/non-UUID/non-v4 → `422`. Invalid/missing/non-duration `for` → `422`. Wrong method on `/wait` → `405`. `data` is optional; when present it must be a JSON object (any nesting), decoded into `JsonValue` and stored as JSONB (absent → SQL `NULL` via an empty-string sentinel through `NULLIF`). `data` is persisted but **not echoed**; a non-object `data` → `422`. `status` is a state machine seeded at `received` (the `waits.status` column defaults to `'received'` with a `CHECK (status IN ('received','waiting'))`).

Duration grammar (strict): `"{integer} {unit}"`, exactly one space, no surrounding/double spaces, lowercase unit, integer `> 0`, plural agreement (`1` → singular, else plural). Units (exact only): `second`/`minute`/`hour`/`day`/`week`. `month`/`year` are rejected — `gleam_time` has no exact constructor for them. Note: the integer is parsed via `int.parse`, which accepts a leading `+` and leading zeros (`"+5 minutes"`, `"05 minutes"` are valid).

Handlers re-assert their own preconditions (`wisp.require_method`, `wisp.require_json`) rather than trusting the router, so they remain correct when called directly — which the unit tests do.

## Testing conventions

- **gleeunit** is the runner; tests are public functions suffixed `_test`.
- **`wisp/simulate`** builds requests in-process (`simulate.request`, `simulate.read_body`) — no live server needed. To send a JSON body, use `simulate.string_body(json) |> request.set_header("content-type", "application/json")` (there is no `simulate.json_body(String)`; the JSON-arg variant takes a `gleam/json.Json`).
- **DB-backed tests run against a live Postgres.** `test/test_helper.gleam` provides `start_pool` (pool from `DATABASE_URL`, size 1), `with_db` (TRUNCATE `waits` then run), `count_waits`, and `dummy_connection` (an unstarted handle for router-only tests). `make test` requires `make db-up && make migrate` first.
- The batch writer is tested by firing `batch.enqueue_async` (non-blocking) from one process and receiving each reply — this fills a batch without deadlocking. Tests cover both flush triggers, the threshold boundary, multiple batches, the error path (duplicate PK → `Error`), and JSONB persistence.
- Test layout mirrors `src/`. Focused unit tests per concern (`duration_unit_test`, `decoder_unit_test`, `encoder_unit_test`, `json_value_unit_test`, `status_unit_test`), DB integration tests (`sql_integration_test`, `batch_test`, `handler_test`), and a router-level integration test (`router_integration_test`).
- Development is test-driven: write the failing test, then the implementation.

## Conventions

- One feature module per route file under `src/notyet/`; keep type + decoder + encoder + handler colocated. Cross-cutting helpers (status, record, batch, json_value) live in focused `src/notyet/wait/*` submodules.
- SQL is authored in `src/notyet/<feature>/sql/*.sql` (one statement per file) and turned into typed Gleam by `make sqlgen`; schema changes go through a cigogne migration (`make migrate-new`), and squirrel must be regenerated against the migrated DB.
- Commits follow Conventional Commits (`feat(scope): ...`), scoped to the layer touched (`wait`, `router`, `server`, `web`, `db`).
- No compound shell commands anywhere (Bash, Makefile, Dockerfile `RUN`, compose `command:`) — one command per line.
